# Enterprise Knowledge Assembly Studio — Prototype Use Case

## 1. Use Case Name

**Customer 360 Enterprise Knowledge Layer**

---

## 2. Business Context

The enterprise has already standardized core data engineering capabilities:

- Data ingestion
- Data foundation and medallion architecture
- Data modelling
- Data products
- Data quality
- Metadata management
- Data governance
- Lineage
- Master data management
- Semantic models
- Unstructured-data processing

However, the assets generated by these capabilities remain distributed across multiple systems and are not assembled into one reusable enterprise knowledge layer.

Examples of distributed knowledge fragments include:

- Customer tables and data products in Databricks or Snowflake
- Semantic definitions in dbt or BI models
- Business terms, owners, and classifications in Atlan
- Golden customer identities in MDM
- Policies and consent documents in SharePoint
- Existing entity relationships in Neo4j
- Customer interaction transcripts and support documents
- Data quality rules and lineage information
- APIs, operational events, and downstream application metadata

The prototype demonstrates how an agentic platform can discover, interpret, connect, validate, govern, and publish these assets as a reusable Customer 360 knowledge product.

---

## 3. Core Conference Story

The demo should communicate the following sequence:

1. Enterprise knowledge already exists, but in fragmented forms.
2. Existing data platforms standardize data production but do not automatically assemble all business meaning, relationships, policies, and provenance.
3. The application creates a knowledge project around a business objective.
4. Agents discover relevant enterprise assets.
5. Agents align concepts, resolve entities, infer relationships, attach policies, and construct provenance.
6. Human reviewers resolve ambiguous or high-risk recommendations.
7. The platform validates semantic quality, relationship quality, provenance, policy coverage, and retrieval readiness.
8. The assembled knowledge layer is published through graph, API, vector, MCP, and agent-ready interfaces.
9. Downstream copilots, AI agents, analytics applications, and search systems consume the governed knowledge product.

## 9. Agentic Assembly Workflow

When the user clicks `Create Project`, start a deterministic multi-step workflow.

### Stage 1 — Asset Discovery

Agents:

- Asset Discovery Agent
- Metadata Interpretation Agent

Actions:

- Read connected source metadata.
- Identify assets relevant to the project scope.
- Assign each asset a knowledge role.
- Detect missing asset categories.
- Produce a source coverage score.

### Stage 2 — Semantic Alignment

Agents:

- Semantic Alignment Agent
- Ontology Mapping Agent

Actions:

- Match source fields to enterprise concepts.
- Align glossary terms to semantic models.
- Detect duplicate or conflicting definitions.
- Generate canonical concept recommendations.

Example conflict:

- `Active Customer` in the semantic model means activity in the last 90 days.
- `Active Customer` in the service platform means an open subscription.

Require a domain owner decision.

### Stage 3 — Entity Resolution

Agent:

- Entity Resolution Agent

Actions:

- Match CRM Customer to Golden Party Record.
- Resolve multiple identifiers.
- Identify households and account hierarchies.
- Record confidence and evidence.

Example accepted mapping:

```text
CRM.Customer_ID C-10482 → MDM.Party_ID P-88991
Confidence: 96%
Evidence: email hash, account number, address similarity, survivorship rule
```

### Stage 4 — Relationship Discovery

Agent:

- Relationship Discovery Agent

Actions:

- Reuse existing Neo4j relationships.
- Infer relationships from foreign keys, semantic mappings, documents, and events.
- Detect duplicate and contradictory relationships.
- Assign relationship confidence and provenance.

### Stage 5 — Policy and Governance Attachment

Agents:

- Policy Mapping Agent
- Lineage Assembly Agent

Actions:

- Attach consent and PII policies to concepts and attributes.
- Map jurisdiction-specific restrictions.
- Build end-to-end provenance.
- Assign owner and steward accountability.

### Stage 6 — Graph Construction

Agent:

- Graph Construction Agent

Actions:

- Construct metadata, lineage, semantic, domain, operational, and governance layers.
- Generate graph schema and graph instances.
- Build a retrieval package and vector index metadata.
- Version the draft knowledge product.

### Stage 7 — Quality and Validation

Agents:

- Knowledge Quality Agent
- Retrieval Evaluation Agent

Actions:

- Validate graph connectivity.
- Validate relationship confidence.
- Check policy coverage.
- Check provenance completeness.
- Run sample RAG groundedness tests.
- Identify unresolved steward reviews.

### Stage 8 — Publication

Agent:

- Publication Agent

Actions:

- Package graph schema.
- Publish graph endpoint.
- Publish vector index.
- Publish REST and GraphQL endpoint metadata.
- Publish MCP tool bundle.
- Register consuming applications.

Publish the knowledge product through APIs, graph endpoints, vector search, and MCP tools.

Show how copilots, agents, analytics, and search consume the knowledge product and how usage feedback informs future improvement.
